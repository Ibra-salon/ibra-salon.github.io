# Ibra-salon · Журнал мастера: инструкция для Claude Code

Журнал парикмахера: визиты, записи наперёд, смены, клиенты без контактов, прайс, статистика, копия в Excel. Пользователь один: мастер со своим телефоном. Интерфейс и тексты на русском.

## Главные правила

- **Данные только на устройстве.** Никаких серверов, баз в облаке, аккаунтов, аналитики, трекеров, внешних запросов с данными. Это требование владельца.
- **Контакты клиентов не хранить.** Ни телефонов, ни соцсетей: мастеру это запрещено в салоне. Клиент — имя или прозвище плюс заметка.
- **Без сборки.** Чистые ES-модули, никаких npm-зависимостей, бандлеров, фреймворков. Внешняя библиотека одна: SheetJS, лежит в `js/vendor/`.
- **Обратная совместимость данных.** Старые данные в телефоне и старые файлы Excel должны продолжать открываться. Новое поле — с безопасным значением по умолчанию в `js/db.js` и в восстановлении в `js/export.js`.

## Структура

- `index.html` — оболочка. `css/app.css` — все стили, цвета через переменные, есть тёмная тема.
- `js/app.js` — запуск, вкладки по `#hash`, регистрация `sw.js`.
- `js/db.js` — хранилище в IndexedDB. Понимает подмножество запросов PostgREST (`select=*,client:clients(name)`, `eq/gte/lte/ilike`, `order`, `limit`). Таблицы: `services`, `clients`, `visits`, `visit_items`, `shifts`, `settings`. Связи для вложенных select описаны в `REL`.
- `js/store.js` — все операции с данными. UI ходит только сюда, не в `db.js`.
- `js/stats.js` — расчёт метрик, чистые функции без DOM.
- `js/export.js` — сборка Excel, сохранение копии (Web Share или скачивание), разбор файла копии и восстановление.
- `js/catalog.js` — константы: источники клиентов, статусы, порядок категорий, прайс для первого запуска (`PRICE_LIST`).
- `js/util.js` — даты, время, деньги (`money()` → «12 500 ₸»), `el()` для создания DOM, `toast()`, `ls()` для мелких настроек.
- `js/ui/*.js` — вкладки (`today`, `calendar`, `clients`, `stats`, `more`), формы (`visit-form`, `shift-form`), выезжающий лист (`sheet`), копия и подсказки (`backup`).
- `sw.js` — офлайн-кэш. Свои файлы: сеть, потом кэш. Шрифты и `vendor`: кэш, потом сеть.

## Бизнес-логика

- Доход мастера = выручка × `master_percent` (по умолчанию 40) / 100 + чаевые целиком.
- Статистика считается только по визитам со статусом «выполнено».
- Загрузка = занятые минуты визитов / минуты смен.
- «Новый» ставится сам, если у клиента ещё не было визитов. Можно снять вручную.
- Название и цена услуги копируются в `visit_items` в момент визита: правка прайса не меняет историю.

## Как менять

1. Правка UI или логики: меняй нужный модуль. Новый файл JS добавь в список `SHELL` в `sw.js` и подними версию `CACHE` (`ibra-v2` → `ibra-v3`).
2. Новое поле в данных: добавь в форму, в `store.js`, значение по умолчанию при загрузке старых данных, столбец в `buildWorkbook()` и разбор в `parseBackup()` в `export.js`.
3. Проверь локально: `python3 -m http.server 8765`, открыть http://localhost:8765/ в узком окне (390 px). Пройди сценарий: смена → визит из двух услуг → запись наперёд → «Пришёл» → статистика → «Сохранить копию» → «Восстановить из файла» в чистом профиле браузера.
4. `node --check` на изменённых JS-файлах.
5. Коммит в `main` и пуш. GitHub Pages обновит сайт за 1–2 минуты. У пользователя новая версия подтянется при следующем открытии с интернетом.

## Чего не делать

- Не добавлять вход, облачную синхронизацию или сбор данных без явной просьбы владельца.
- Не удалять и не переименовывать столбцы в Excel: на них завязано восстановление.
- Не менять имя базы IndexedDB (`ibra-journal`) и ключ (`tables`): пользователь потеряет данные.
